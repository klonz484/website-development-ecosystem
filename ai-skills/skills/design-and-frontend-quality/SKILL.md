# Design and Frontend Quality

## Use when
Designing or improving websites, dashboards, SaaS products, forms, navigation, design systems, presentations with visual design, or reviewing UI quality.

## Workflow
1. Identify users, primary tasks, device contexts, accessibility needs, brand constraints and success criteria.
2. Inspect the existing product and design system before inventing a new visual language. Preserve consistency unless a redesign is intended.
3. Define information hierarchy, layout, interaction states, responsive behavior, typography, spacing, color roles and component states.
4. Use semantic HTML, keyboard-operable controls, visible focus, sufficient contrast, accessible names, reduced-motion support and clear error/help states.
5. Build reusable tokens/components only where repetition justifies them. Avoid decorative complexity, gratuitous gradients, arbitrary animation and generic AI-generated visual tropes.
6. Validate at mobile/tablet/desktop widths; test empty, loading, error, success, disabled and long-content states.
7. Review screenshots or rendered UI against the task; run automated accessibility checks where available and manually inspect keyboard flow.

## Deliverable
Explain design rationale, component/system changes, responsive behavior, accessibility considerations and what was actually tested. Do not claim visual verification without seeing the rendered result.
