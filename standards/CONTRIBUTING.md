# Contributing

1. Open or update an issue describing the problem and acceptance criteria.
2. Create a short-lived branch from the default branch.
3. Make a focused change; avoid unrelated refactors.
4. Add or update tests and documentation.
5. Run local quality checks.
6. Open a pull request using the template.
7. Review CI, security, accessibility and deployment impact.
8. Resolve feedback and merge using the approved strategy.
9. Delete the branch and verify the result.

PRs explain why, scope, risks, alternatives, rollout/rollback, test evidence and known limitations. Include screenshots for visual changes with sensitive data removed. Identify new dependencies and licensing/provenance. Shared assets require a usage example, compatibility, tests, owner and maintenance plan.

Use clear imperative commit messages. Never commit secrets, personal data, private keys or unlicensed copied material. Review correctness, readability, security, accessibility, performance, tests, migrations and operations. Be respectful and specific.
